# Форматы JSON и семантика движка

Единый источник правды — `Content/`. Общая БД для **всех** глав лежит в
`Content/rome/` (историческое имя): `characters.json`, `scenes.json`, `rules.json`.
Уровни — `Content/<epoch>/levels/<id>.json`, где epoch ∈ rome, tudor, revolution,
empire, borgia, byzantium (+новые). Приложения читают не `Content/`, а бандл-копии —
их обновляет `tools/sync_content.py`.

Референсный симулятор (зеркало C#-движка 1:1): `tools/simulate.py`.

## Уровень

```json
{
  "id": "caesar_assassination",        // snake_case, уникален глобально
  "order": 80,                          // позиция в главе, шаг 10 (вставки: 53, 55…)
  "title": "И ты, Брут?",              // русский — исходный язык всего контента
  "epoch": "rome",
  "panels": 3,                          // 2–3 панели комикса
  "scenes": ["back_room", "senate", "forum"],   // id из scenes.json; сцен ≥ panels (лишние = приманки)
  "characters": ["caesar", "brutus", "cassius", "antony"],  // 3–5, с приманками
  "initialState": {                     // опционально
    "flags": {"cleopatra": ["locked_out"]},
    "relations": [["ally_of", "brutus", "caesar"]]
  },
  "initialText": "Клеопатра — чужестранка, стража во дворец её не впускает",  // опц. завязка
  "goal": { "all": [
    {"flag": {"char": "caesar", "is": "dead"}},
    {"relation": {"rel": "betrayed", "from": "brutus", "to": "caesar"}},
    {"not": {"flag": {"char": "antony", "is": "plotting"}}}
  ]},                                   // узлы: all / any / not / flag / relation
  "goalText": "Друг Брут вступает в заговор и убивает Цезаря",
  "goalHint": "Заговор Брут плетёт с Кассием — не с самим Цезарем.",
  "solution": [                         // эталон; порядок персонажей = роли сцены!
    {"scene": "forum", "characters": ["caesar", "brutus"]},
    {"scene": "back_room", "characters": ["brutus", "cassius"]},
    {"scene": "senate", "characters": ["brutus", "caesar"]}
  ],
  "factCard": {
    "accuracy": "fact",                 // fact | simplification | legend
    "text": "15 марта 44 г. до н.э. …", // 2–4 предложения, даты, деталь-изюминка
    "source": "Светоний, «Жизнь двенадцати цезарей»"
  },
  "music": "tension",                   // rome: romance|battle|tension|ceremony; прочие: <epoch>_<mood>
  "cover": "senate",                    // опц.: сцена-обложка уровня на карте
  "act": "Акт II · Царица и диктатор"   // подпись акта (рус.)
}
```

## Сцена

```json
{"id": "senate", "name": "Сенат", "tags": ["senate"], "slots": 2,
 "emoji": "⚖️", "action": "покушение", "actionIcon": "icon_dead",
 "roles": ["убийца", "жертва"]}
```

- `slots`: 1–3 (почти все 2). `tags` — по ним матчатся правила.
- `roles` (опц.): у слотов есть смысл, порядок персонажей в панели важен;
  без `roles` порядок косметический (канонизация сортировкой).
- **Если сцена объявляет `roles`, правила этой сцены обязаны фиксировать акторов
  через `slot`** — иначе роли в UI ничем не подкреплены: любая перестановка
  персонажей внутри панели тоже решает уровень, каноника раздувается фиктивными
  дублями («убийца» и «жертва» местами — а победа всё равно засчитана). Признак
  болезни: canonical делится на число перестановок ролей (так у `pompey_death`
  «4 канонических» = 1 реальное × 4 порядка слотов).
- `action`/`actionIcon` — подпись действия сцены в UI.

## Персонаж

```json
{"id": "caesar", "name": "Юлий Цезарь", "tags": ["ruler", "roman"], "emoji": "🧓"}
```

Теги — «сущность» персонажа (roman, senator, servant, charming, rival, ruler…),
они статичны; всё изменяемое — флаги.

## Правило

```json
{
  "id": "betrayal_kill",
  "comment": "Заговорщик убивает союзника в Сенате и становится предателем",
  "priority": 10,
  "trigger": {
    "sceneTags": ["senate"],            // сцена должна иметь ВСЕ эти теги
    "actors": [
      {"var": "A", "flags": ["plotting"], "relations": [{"rel": "ally_of", "to": "B"}]},
      {"var": "B"}
    ]
  },
  "effects": [
    {"type": "setFlag", "target": "B", "flag": "dead"},
    {"type": "addRelation", "rel": "betrayed", "from": "A", "to": "B"}
  ]
}
```

Актор: `tags` (все обязаны быть у персонажа), `flags` (все), `notFlags` (ни одного),
`relations` (к другим переменным правила), `slot` (жёсткая привязка к позиции N
панели — для сцен с ролями: слот 0 — убийца, слот 1 — жертва).
Эффекты: `setFlag`, `removeFlag`, `addRelation`, `removeRelation`.

## Семантика исполнения (что важно дизайнеру)

- Панели применяются слева направо; правила внутри панели — по убыванию `priority`,
  срабатывают **все** подходящие, со **всеми** подходящими биндингами
  (симметричное правило типа `befriend` сработает дважды: A→B и B→A).
- Эффекты видны следующим правилам той же панели; биндинг перепроверяется
  (умерший в этой же панели больше не матчится).
- `dead` — универсальный стоп: мёртвые не попадают в биндинги вовсе.
- Отношения направленные: `loves(a→b)` ≠ `loves(b→a)`. Цель `relation` проверяет
  направление буквально.
- Игрок может оставить панель пустой или заполнить частично — решателю доступны
  все размещения от 0 до `slots` персонажей.

## Гигиена общей БД (важно!)

Правила, сцены и персонажи — общие на все главы. Поэтому:
- **Не меняй** существующие правила/сцены под нужды нового уровня — сломаешь чужие
  уровни. Добавляй новые правила и гейти их уникальным sceneTag или тегом персонажа
  своей эпохи (`senate_outrage` живёт только на сценах с тегом `outrage_r`).
- Переиспользовать универсальные правила (`befriend`, `conspire`, `smuggle`) — можно
  и нужно: их «жадность» сама по себе источник ловушек.
- После правок общей БД прогони `python3 tools/simulate.py Content/rome --all` —
  все ~80 уровней должны остаться валидными.
