# Level Content — контент-дизайн уровней History Teller

Уровень — это исторический эпизод, закодированный в механику: игрок расставляет
персонажей по сценам в 2–3 панелях комикса, правила движка срабатывают, и если
итоговое состояние мира удовлетворяет цели — история «случилась». Хороший уровень
это **мини-теорема**: пройдя его, игрок понимает, *почему* событие произошло именно так.

Три режима работы (определи, какой просит пользователь):
1. **Оценить уровень** → раздел «Рубрика», дай вердикт и **остановись** — не правь ничего, пока не скажут «делай».
2. **Улучшить уровень** → рубрика → найди слабейший критерий → точечная правка → валидация.
3. **Создать уровень/главу** → «Воркфлоу создания» ниже.

Перед любой работой прочитай `references/format.md` (схемы JSON + семантика движка)
и `references/exemplars.md` (разбор эталонных уровней — калибровка качества).
Команды валидации и пайплайна — `references/pipeline.md`.

## Как работает движок (минимум для дизайна)

- Панель = (сцена, упорядоченный список персонажей). Панели применяются слева направо.
- Правило срабатывает, если у сцены есть все `sceneTags` правила и в панели нашлись
  персонажи под всех акторов (совпали `tags` персонажа, `flags`/`notFlags` состояния, `relations`).
- В одной панели срабатывают **все** подходящие правила (по убыванию priority), эффекты
  видны следующим правилам той же панели. Мёртвые (`dead`) в биндинги не попадают.
- Цель — дерево `all`/`any`/`not` над `flag`/`relation`.
- Состояние мира: флаги персонажей + направленные отношения. Больше ничего нет.

## Критерии качества (все обязательны, кроме последнего)

Из эталонов `cleopatra_charm`, `cleopatra_throne`, `cleopatra_rome`, `caesar_assassination`:

1. **Есть где ошибиться.** Минимум две *осмысленные* ловушки — расстановки, которые
   выглядят логично, но проваливают уровень. Мёртвые токены (персонаж/сцена, не нужные
   в решении) — это хорошо, это приманка. Типы ловушек — ниже.
2. **Историчность.** Каждый бит решения соответствует реальному событию, а ловушки —
   реальным «а что если бы»: механика и есть исторический аргумент. `factCard` честно
   помечает `accuracy` (`fact` / `simplification` / `legend`) и даёт первоисточник.
3. **Тугой distinct.** Канонических решений мало: ≤ 4 отлично, ≤ 8 приемлемо
   (валидатор ругается выше 8) — при пространстве перебора в тысячи вариантов.
4. **Тексты — драматургия, не инструкция.** `initialText` — завязка конфликта,
   `goalText` — заголовок серии («Друг Брут вступает в заговор и убивает Цезаря»),
   `goalHint` — направление мысли, не спойлер («Заговор Брут плетёт с Кассием — не с
   самим Цезарем»), `factCard` — награда: «как было на самом деле» + деталь-изюминка
   (ковёр Аполлодора, греческое «И ты, дитя?» вместо шекспировского).
5. **Порядок панелей несёт смысл** (бонус). Цепочка флагов заставляет играть события
   в исторической последовательности: сначала дружба — потом заговор — потом кинжал.

## Арсенал ловушек

Проектируя уровень, выбери минимум две — разных типов:

- **Персонаж-приманка + негативная цель.** В ростере есть тот, кого класть *нельзя*.
  `cleopatra_charm`: Антоний в ростере, цель требует `not(antony loves cleopatra)`,
  а правило `charm` влюбляет любого собеседника — положил Антония к Клеопатре в
  романтическую сцену — проиграл. Приманка должна *притягивать* (Антоний исторически
  и правда любил Клеопатру — игрок тянется).
- **Флаг-замок.** Стартовый флаг блокирует «очевидный» ход через `notFlags`.
  `cleopatra_charm`: `locked_out` на Клеопатре гасит `charm` — сначала пронеси её
  через тайный ход (`smuggle` снимает флаг), потом очаровывай.
- **Цепочка флагов = принудительный порядок.** Каждое правило требует флаг,
  который ставит предыдущее. `cleopatra_throne`: `conquer`→`conqueror`,
  `back_ruler` требует `conqueror` и ставит `backed`, `enthrone` требует `backed`.
- **Жадное правило-ловушка.** Общее правило срабатывает на «лишних» и портит цель.
  `caesar_assassination`: `conspire` делает заговорщиками *любых двоих* в тайной
  комнате, а цель требует `not(antony plotting)` — Антония в тайную комнату нельзя.
- **Сцена-приманка.** Сцен больше, чем панелей; одна-две правдоподобны, но не ведут
  к цели (форум в `cleopatra_charm` — «публично подружить» не решает).
- **Предусловие-отношение.** Эффект требует заранее построенного отношения.
  `betrayal_kill` требует `plotting` **и** `ally_of` к жертве: предать может только
  друг — сама механика говорит «И ты, Брут?».

## Воркфлоу создания уровня

1. **Эпизод.** Выбери исторический момент с конфликтом и поворотом/иронией.
   Спроси себя: какую «теорему» игрок должен унести? (Не «Цезаря убили», а
   «Цезаря убил его друг, и толкнули сенат на это царские амбиции».)
2. **Биты.** Разложи эпизод на 2–3 бита — по одному ключевому правилу на панель.
   Каждый бит = глагол: пронести, очаровать, разбить, короновать, предать.
3. **Правила.** Сначала переиспользуй общие (`befriend`, `conspire`, `assassinate`…),
   специфику добавляй новыми правилами с **уникальными для уровня sceneTags** —
   не мутируй существующие правила и чужие сцены (изменишь — сломаешь чужой уровень;
   независимость уровней важнее DRY). Общая БД одна на все главы:
   `Content/rome/{rules,scenes,characters}.json` — историческое имя папки.
4. **Ловушки.** Добавь ≥2 из арсенала. Ростер: 3–5 персонажей, сцен на 1–2 больше,
   чем панелей. Затем проверь себя вопросом: «какими тремя способами игрок,
   думающий логично, проиграет?» Если способов нет — уровень скучный, вернись.
5. **JSON уровня** в `Content/<epoch>/levels/<id>.json` (схема — `references/format.md`;
   `order` с шагом 10, `music` — `<epoch>_<mood>`, у rome без префикса).
6. **Валидация.** `python3 tools/simulate.py Content/rome Content/<epoch>/levels/<id>.json`
   — эталонное решение обязано проходить, канонических решений ≤ 8. Слишком много —
   ужесточай цель (добавь `not`-условие) или сузь правила флагом-замком.
   Проверь и то, что ловушки реально ловят: прогони «соблазнительную» расстановку
   и убедись, что она НЕ решает уровень.
7. **Тексты и factCard** — по критерию 4. Затем i18n + синк бандлов
   (`references/pipeline.md`) — без `sync_content.py` приложение правок не увидит.

## Рубрика оценки уровня

Прогони уровень через валидатор, прочитай его правила, потом оцени по пяти
критериям (✅ / ⚠️ / ❌ с одной строкой обоснования):

| Критерий | Вопрос |
|---|---|
| Ловушки | Назови конкретные проигрышные расстановки. Их ≥2 и они соблазнительны? |
| Историчность | Каждый бит = событие? factCard честен и с изюминкой? |
| Distinct | Сколько канонических решений на каком пространстве? |
| Тексты | goalHint направляет, не спойлерит? factCard — награда? |
| Порядок | Порядок панелей вынужден механикой? (бонус) |

Вердикт: «эталон / хорош / нужна правка X / переделать». **После вердикта — стоп.**
Реализуй правки только после явного «делай».

## Definition of done (уровень)

- [ ] `simulate.py`: reference OK, canonical ≤ 8, ловушки проверены вручную
- [ ] ≥2 ловушки разных типов, у каждой — историческое «а что если»
- [ ] Сцены с `roles` подкреплены `slot`-ами в правилах (иначе каноника — фикция)
- [ ] Ни одно общее правило/сцена не изменены (только добавлены новые); менять
      существующее правило можно лишь после grep-проверки, что его сцены/теги
      использует только твой уровень, — и с регрессией `--all`
- [ ] Новый уровень зарегистрирован в iOS: `RomeContent.swift` → `levelIds`
      (Android подхватывает сам)
- [ ] factCard: accuracy честный, источник назван, есть деталь-изюминка
- [ ] i18n: `tools/i18n/extract.py` → `translate.py` (9 языков)
- [ ] `tools/sync_content.py` прогнан (iOS + Android бандлы)

## Новая глава (кратко)

Формат устоялся: **13 уровней, 3 акта**, сквозная арка вокруг 2–3 фигур
(возвышение → триумф → падение). Дополнительно к уровням: персонажи+арт
(`tools/genart.py`, пайплайн Nano Banana), сцены, музыка 4 трека
(`tools/make_epoch_music.py`), ключи главы в `tools/i18n/extract.py`
(chapter/map/act — руками), регистрация эпохи в приложениях.
Детали — `references/pipeline.md`. Проектируй главу как сериал: у каждого
уровня свой «эпизодный» конфликт, у актов — общий сюжетный поворот.
