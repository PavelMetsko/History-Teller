# Счётчики прохождения

Отвечает ровно на один вопрос: **играет ли в это кто-нибудь и докуда доходит**.

В базе лежат строки вида `done:rome:sabines → 14`. Ни идентификатора установки, ни времени,
ни страны. Поэтому «этот покупатель играл до покупки?» отсюда узнать нельзя — для такого
вопроса пришлось бы связывать события одного человека, а связывать нечем. Это цена того,
что политика приватности остаётся прежней.

## Что шлёт приложение

Каждый ключ уходит максимум один раз за установку (отправленное запоминается на устройстве),
и только из релизной сборки — debug не считается.

| ключ | когда |
|---|---|
| `open:<глава>` | игрок впервые открыл карту главы |
| `done:<глава>:<уровень>` | игрок впервые прошёл эпизод |

Не доехало (офлайн) — ключ ждёт в очереди и уходит при следующем запуске.

## Развернуть

```bash
cd stats
npx wrangler d1 create history-teller-stats
```

id из вывода вписать в `wrangler.toml`, затем:

```bash
npx wrangler d1 execute history-teller-stats --remote --file schema.sql
npx wrangler secret put READ_TOKEN
npx wrangler deploy
```

## Посмотреть

```bash
curl "https://stats.historyteller.app/?token=$READ_TOKEN"
```

```
ОТКРЫЛИ ГЛАВУ

  england                         1

ПРОШЛИ ЭПИЗОД

    sabines                      31
    lucretia                     22
```

Воронка внутри главы отсортирована по убыванию — видно, на каком эпизоде люди отваливаются.

## Чего здесь нет

Приложение ответ Worker'а не читает и на его недоступность не реагирует никак: счётчики —
побочная штука, они не должны иметь возможности сломать игру. Если Worker выключить,
приложение просто продолжит копить ключи в очереди.
