# Редактор контента

Правка уровней, текстов и арта с проверкой тем же движком, что стоит в игре.

## Запуск

```sh
./tools/build_editor.sh          # собирает движок в JS (нужен после правок :engine)
python3 tools/editor_server.py   # http://localhost:8080/editor/
```

`build_editor.sh` нужен после изменений в `android/engine`. «Опубликовать» вызывает его сама:
собранный движок легко забыть пересобрать, и тогда валидация в браузере молча считает по старой
логике — так уже случалось после выноса текстов.

## Где что лежит

```
Content/                    источник правды, из него собирается всё остальное
  chapters.json             главы: номер, обложка, иконка, платность
  disabled.json             выключенные уровни — рубильник, действует без релиза
  <эпоха>/levels/<id>.json  механика уровня: каст, сцены, цель, эталон
  rome/{characters,scenes,rules}.json   общая база (лежит в rome/ исторически)
  i18n/<язык>.json          ВСЕ тексты, включая русский
  art/*.webp, audio/*.m4a   ассеты
```

Текстов в файлах уровней нет намеренно: раньше русский дублировался и в уровне, и в каталоге,
и рано или поздно они бы разъехались. Теперь уровень описывает только механику.

## Как это доходит до игрока

```
правка → Сохранить → Опубликовать → R2 → игра при следующем запуске
```

«Опубликовать» гоняет валидатор, собирает манифест и заливает в R2. Сломанный контент не
публикуется: при нерешаемом уровне или неверном эталоне валидатор возвращает ненулевой код,
и заливка не начинается.

В облако уходят только изменившиеся объекты: файлы адресуются по sha256, поэтому правка одной
подсказки — это один файл на ~100 КБ, а не весь контент.

## Валидация

Кнопка «Проверить» гоняет солвер — тот же, что в игре (`:engine-js` собирается из тех же
исходников, что `:engine`).

| | |
|---|---|
| `решений` | сколько всего расстановок приводят к цели |
| `различимых` | сколько среди них принципиально разных |
| `перебор` | размер пространства поиска |

Ориентир по «различимым»: **1** — идеал, **2–3** — допустимо, если все варианты читаются как
одна и та же история, **больше** — цель настолько свободна, что игрок дойдёт случайно.

Солвер брутфорсный: тяжёлые уровни (`triumvirate`, `bloody_mary`) считаются десятки секунд.
Поэтому он живёт в Web Worker — интерфейс не замирает, — а результаты кешируются по содержимому:
повторная проверка мгновенная.

Любая правка механики прячет прежний вердикт: он моментально перестаёт быть правдой.

## Загрузка арта

Кнопка «+ арт». Браузер сам уменьшает и жмёт в WebP по тем же правилам, что
`tools/optimize_art.py`: персонажи до 768 по высоте, сцены до 1024, качество 82.
Имя собирается как `char_<id>` или `scene_<id>`.

## Выложенная версия

`history-teller-editor.pages.dev` — **только просмотр**. Запись идёт через Worker, а он закрыт:
у него токен с правом записи в репозиторий, и открывать его в интернет без защиты нельзя.
Cloudflare Access для этого требует собственного домена, которого пока нет.

Когда домен появится, включается всё разом: Access на редактор и Worker, плюс боевая раздача
контента вместо `r2.dev` (его Cloudflare троттлит и для продакшена не рекомендует).

## Что чинить руками

Дерево цели правится как JSON — конструктор предикатов стоил бы дороже всего остального
вместе, а формы целей повторяются, и копировать их с соседнего уровня быстрее.

Публикация через GitHub Actions настроена (`.github/workflows/publish-content.yml`, секреты R2
на месте), но ни разу не выполнялась: в день настройки у GitHub была авария Actions.
