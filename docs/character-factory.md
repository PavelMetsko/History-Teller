# Фабрика персонажей — план и промт для запуска

Цель: свой редактор и сборщик персонажей, чтобы больше не платить нейросети за каждый спрайт. Из одной библиотеки деталей собираем **всех** персонажей игры (сейчас 582 персонажа, 864 файла с позами) в одном общем стиле и во всех нужных позах.

Документ — задание для сессии, которая будет это строить. Его можно отдать целиком.

---

## 1. Принципы

1. **0 zł на персонажа.** Нейросеть не рисует ни одного персонажа. Допустимо одно: точечно сгенерировать референсы деталей, если без этого не обойтись, и только с явного «делай» пользователя.
2. **Рецепт — источник правды.** Персонаж = JSON-рецепт (какие детали, какие цвета). PNG/WebP — артефакт сборки, его всегда можно пересобрать. Поправили деталь — пересобрали всех, кто её носит.
3. **Один риг для всех.** Одно тело с суставами, одна поза = набор углов. Поза рисуется сама для любого персонажа, без доп. картинок.
4. **Совместимость с игрой без правки кода.** На выходе те же файлы, что сейчас: `Content/art/char_<id>.webp` и `char_<id>_{dead,defeated,plot,triumph}.webp`, 512×768 RGBA, рост фигуры 0.77 кадра, линия пола 16/768 снизу (константы из `tools/normalize_sprites.py`). Игра уже умеет брать позы, если они есть (`ios/Modules/GameContent/Sources/GameAssets.swift`).
5. **Старый арт не трогаем до одобрения.** Новый арт кладём в `Content/art_v2/`, переключаем главу целиком, когда пользователь принял лист.

## 2. Ключевое решение: вектор (SVG) + риг

Детали — **SVG**, а не растровые куски нейросетевых картинок.

Почему:
- Позы требуют, чтобы руки, ноги и голова были отдельными деталями. Растровые спрайты слиты в одну картинку, их не разрезать на конечности.
- Наш стиль (чиби, большая голова, толстый тёмно-коричневый контур, плоские цвета, мягкая тень) хорошо ложится на вектор: контур = `stroke`, тень = полупрозрачная заливка или градиент.
- Цвета — переменные (`--primary`, `--secondary`, `--trim`, `--skin`, `--hair`), поэтому перекраска точная, без хака с оттенками, как в kitbash.
- Детали можно рисовать кодом и правками SVG вручную. Нейросеть для этого не нужна.

Компромисс: картинка будет чище и «площе», чем нынешние спрайты от Nano Banana. Поэтому **этап 0 — проверка стиля** (раздел 8): пользователь сравнивает 3 новых персонажа со старыми и принимает или правит стиль до того, как мы рисуем библиотеку.

## 3. Риг

Холст 512×768, точка отсчёта — таз. Кости и порядок слоёв (снизу вверх):

| Кость | Родитель | Что крепится |
|---|---|---|
| `pelvis` (корень) | — | штаны или юбка (верх) |
| `leg_l`, `leg_r` | pelvis | штанины, сапоги |
| `torso` | pelvis | рубаха, доспех, мундир, плащ спереди |
| `cape_back` | torso | плащ сзади, мантия (рисуется под всем) |
| `arm_upper_l/r` | torso | рукава |
| `arm_lower_l/r` | arm_upper | манжеты, перчатки |
| `hand_l/r` | arm_lower | кисть + предмет (`held`) |
| `head` | torso | голова, уши, лицо, волосы, борода, головной убор |

Порядок отрисовки: `cape_back` → `hair_back` → дальняя рука → ноги → туловище и одежда → ближняя рука → голова → лицо (глаза, брови, нос, рот) → борода → `hair_front` → головной убор → предмет в руке.

Пропорции чиби: голова ~45 % роста, как у нынешних спрайтов (голова у всех на одной высоте: верх силуэта ~y=161, центр лица по X ~255).

## 4. Позы и выражения

Поза = углы суставов + смещение корня + выражение лица. Всё в одном файле `factory/poses.json`.

| Поза | Файл | Тело | Лицо |
|---|---|---|---|
| base | `char_<id>` | стоя, руки опущены | нейтральное |
| triumph | `_triumph` | руки вверх или кулак вверх, грудь вперёд | широкая улыбка |
| defeated | `_defeated` | плечи опущены, голова вниз, руки висят | брови домиком, рот вниз |
| plot | `_plot` | наклон вперёд, руки потирают друг друга у груди | хитрые глаза, ухмылка |
| dead | `_dead` | лежит (весь риг повёрнут на 90°), руки раскинуты | глаза-крестики или закрыты |

У каждой детали лица есть варианты под выражения (`eyes_round.neutral`, `eyes_round.happy`, `eyes_round.closed` и т. д.), поэтому выражение меняется само.

## 5. Библиотека деталей

Папка `factory/parts/<slot>/<id>.svg` + `factory/parts/index.json` с метаданными: слот, к какой кости крепится, точка крепления, цветовые каналы, теги эпохи (`rome`, `medieval`, `renaissance`, `c18`, `c19`, `byzantine`, `oriental`, `russian`, `polish`).

Минимум на старт (MVP, одна эпоха — Польша Средневековье–XVIII в.):

| Слот | MVP | Полная библиотека |
|---|---|---|
| тело: мужское / женское / ребёнок / полное | 2 | 4 |
| кожа (цвета) | 5 | 8 |
| глаза (×4 выражения) | 4 | 8 |
| брови | 4 | 8 |
| нос | 4 | 6 |
| рот (×4 выражения) | 3 | 6 |
| борода / усы | 6 | 14 |
| волосы (перед + зад) | 8 | 25 |
| головной убор | 10 | 40 (короны, шлемы, меховые шапки, конфедератка, мациеювка, митра, тюрбан, лавровый венок, треуголка, двууголка, кивер, чепцы, вуали) |
| туловище (одежда) | 10 | 60 (тога, туника, кольчуга, латы, жупан, кунтуш, мантия, ряса, камзол, мундиры, платья) |
| рукава | под каждое туловище | — |
| ноги / обувь | 5 | 15 |
| плащ / мантия сзади | 3 | 10 |
| предмет в руке | 6 | 25 (меч, сабля, булава, скипетр, свиток, книга, перо, лампа, коса, копьё, щит, крест) |

Правила рисования деталей:
- Контур: `stroke="#3b2418"` (сверить с нынешними спрайтами), толщина одна для всех деталей. Контуры соседних деталей должны сливаться, без двойной линии на стыке: стык прячем под верхнюю деталь.
- Цвета только через переменные каналов, ничего жёстко не прошиваем.
- Тень: одна полупрозрачная тёмная форма снизу-справа на каждой детали, без сложных градиентов.

## 6. Рецепт персонажа

`factory/recipes/<id>.json`:

```json
{
  "id": "sobieski",
  "body": "male",
  "skin": "light_2",
  "head": { "eyes": "round", "brows": "thick", "nose": "big", "mouth": "smile",
            "beard": "moustache_long", "hair": "shaved_top", "hat": "kolpak_feather" },
  "outfit": { "torso": "hussar_armor", "legs": "boots_red", "cape": "leopard_skin" },
  "held": { "right": "sabre", "left": "bulawa" },
  "colors": { "primary": "#9b1c1c", "secondary": "#c9a227", "trim": "#e8e1d4", "hair": "#6b4a2b" },
  "tweak": { "hat": { "dy": -4 } },
  "poses": ["base", "triumph", "defeated", "plot", "dead"]
}
```

## 7. Редактор и сборщик

**Редактор** — локальная веб-страница без сборки, `factory/editor/index.html` + JS, запуск через `.claude/launch.json` (добавить конфиг `factory` на порту 8091).

Что в нём есть:
- Слева — слоты с превью деталей, фильтр по эпохе.
- В центре — персонаж; справа от него сразу **все 5 поз**, чтобы видеть, не ломается ли что-то в позе.
- Рядом — **старый спрайт** этого же `id`, если есть, для сравнения.
- Справа — цвета каналов (палитры по эпохам + свободный выбор), тонкая подгонка детали (сдвиг ±10 px, масштаб ±10 %).
- Поиск по касту из `Content/rome/characters.json`: открыть персонажа — загрузить рецепт или создать пустой.
- Кнопка «Случайный в рамках эпохи» — для массовки.
- «Сохранить» пишет рецепт в `factory/recipes/`. Сохранять из браузера в файлы — через маленький локальный сервер на Python (`factory/server.py`, стандартная библиотека), а не через ручное скачивание.

**Сборщик** — `factory/build.py`:
- рецепты → SVG → PNG → WebP 512×768 в `Content/art_v2/` (растеризация через `resvg` или Chromium headless; выбрать то, что ставится без проблем на этом маке);
- все позы из рецепта;
- нормализация роста и линии пола по константам из `normalize_sprites.py`;
- контактный лист `factory/out/sheet_<chapter>.png` со старым и новым спрайтом рядом;
- идемпотентно: пересобирает только то, у чего изменились рецепт или детали.

## 8. Этапы и критерии приёмки

| Этап | Что делаем | Готово, когда |
|---|---|---|
| **0. Проверка стиля** | Риг, мужское и женское тело, минимум деталей. Собрать 3 персонажа (Собеский, Ядвига, Пилсудский) во всех 5 позах | Пользователь сказал «стиль ок» по листу «старый / новый» |
| **1. Редактор и сборщик** | Всё из раздела 7 | Пользователь сам собрал в редакторе персонажа, и он появился в `Content/art_v2/` |
| **2. Библиотека MVP** | Детали из таблицы раздела 5, колонка MVP | Собраны все 12 звёзд Польши и 10 человек второго плана |
| **3. Польша** | Весь каст Польши из `docs/countries/poland.md` (~150 персонажей) | Лист каста принят, позы не ломаются |
| **4. Миграция глав** | Рим → Англия → Франция → Россия → Италия → Византия: рецепты для всех, библиотека дорастает до полной | Глава переключена на `art_v2`, старые файлы остались в git |
| **5. Уборка** | Удалить старые позы, ставшие ненужными, обновить `publish_content.py` | Один источник арта — рецепты |

Черновики рецептов для миграции пишет Claude: смотрит на старый спрайт (контактные листы по 30 штук) и подбирает детали. Это не стоит денег за генерацию. Пользователь правит в редакторе только то, что не понравилось.

## 9. Риски

- **Стиль.** Вектор будет проще нынешних картинок. Если на этапе 0 стиль не принят, второй вариант: растровые детали (один раз сгенерировать библиотеку деталей Nano Banana по 6–9 штук на картинку, ~3–5 zł), риг тот же. Позы в этом варианте хуже: конечности придётся рисовать отдельно.
- **Смешение стилей.** Пока миграция не закончена, в польском плейлисте смежные уровни «России» и «Франции» будут в старом стиле. Варианты: мигрировать сначала персонажей смежных уровней или принять временное смешение.
- **Объём библиотеки.** 864 файла = 582 персонажа × позы. Позы теперь бесплатные, но на всю игру нужна полная библиотека (~250 деталей). Рисовать её по эпохам, по мере миграции глав.
- **Узнаваемость.** Знаменитые лица (Цезарь, Наполеон, Генрих VIII) должны остаться узнаваемыми. Для них разрешены уникальные детали (`hair_napoleon`, `hat_bicorne_napoleon`).

## 10. Чего не делать

- Не генерировать персонажей нейросетью, ни одного, без явного «делай».
- Не перезаписывать `Content/art/*` до приёмки главы.
- Не менять код игры ради фабрики: на выходе те же имена и размеры файлов.

---

## Промт для запуска

> Строим фабрику персонажей по `docs/character-factory.md`. Начни с этапа 0: риг, мужское и женское тело, минимальный набор SVG-деталей, сборка Собеского, Ядвиги и Пилсудского во всех 5 позах, контактный лист «старый / новый». Нейросеть для картинок не используй. Перед стартом посмотри 10–15 нынешних спрайтов в `Content/art`, чтобы попасть в контур, пропорции и палитру. Остановись после листа этапа 0 и жди моей оценки стиля.
